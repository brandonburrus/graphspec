# docs/ - the graphspec.dev documentation site

Astro plus [Starlight](https://starlight.astro.build), deployed to GitHub Pages at
graphspec.dev by `.github/workflows/docs.yml` on release, or manually via `workflow_dispatch`.

It is a pnpm workspace package named `graphspec-docs`, so a root `pnpm install` covers it and
`pnpm --filter graphspec-docs <script>` runs its scripts.

```bash
pnpm --filter graphspec-docs dev     # localhost:4321
pnpm --filter graphspec-docs build   # into docs/dist
```

## Layout

| Path | What it is |
|------|------------|
| `astro.config.mjs` | Site URL, sidebar order, code themes, fonts |
| `src/content/docs/` | Every page. The file path is the URL path |
| `src/styles/theme.css` | The entire design system, as Starlight token overrides |
| `src/assets/mark.svg` | Header logo, inherits `currentColor` |
| `public/CNAME` | The custom domain. Removing it breaks graphspec.dev |

## Design system

Warm neutral paper and ink with a single burnt-amber accent, IBM Plex Sans for prose and IBM
Plex Mono for code and the wordmark. Both themes are defined in full: Starlight ships dark on
bare `:root` and light under `:root[data-theme="light"]`, so a color defined in only one place
breaks the other mode.

Constraints worth keeping:

- **One accent.** The amber is the only accent. This is why the code theme is `vitesse`: the
  Shiki defaults highlight in blues that fight it.
- **Product register, not marketing.** Density high, motion minimal, color transitions only.
  No transform hovers, no scroll choreography.
- **Contrast.** Body and muted text clear 4.5:1 in both modes. Check any new color.

## Gotchas

- **Never put an `AGENTS.md` inside `src/content/docs/`.** Every file there becomes a page,
  so it would publish as documentation. This file lives at `docs/` for that reason.
- **Frontmatter values containing `: ` must be quoted.** An unquoted `description` with a
  colon is a YAML parse error that fails the build with a confusing "bad indentation" message.
- **Do not set `--sl-content-width` on `.sl-markdown-content`.** That variable sizes the
  layout grid higher up; overriding it there widens code blocks out from under their scroll
  container and pushes them under the table of contents.
- **`.main-pane` needs `min-width: 0`.** It is a flex item, and the `min-width: auto` default
  makes it refuse to shrink below its widest child, so one long code line scrolls the whole
  page sideways. `theme.css` sets this; removing it reintroduces the bug.
- **Sidebar entries are explicit** in `astro.config.mjs`, not autogenerated. A new page needs
  a sidebar entry or it is reachable only by search and direct link.

## Writing conventions

- No em dashes or en dashes anywhere in visible copy. Restructure with commas, colons,
  parentheses, or separate sentences.
- Every command and every output block is copied from a real run. If you change CLI behavior,
  re-run the affected examples rather than editing them by hand: the docs claim they are real.
- Cross-link with absolute paths and a trailing slash (`/cli/graph/`). The build has no link
  checker, so a typo ships silently.
